# Qurulma mərhələləri və qəbul meyarları

Versiya: 1.0 · 08.09.2026 · Bu meyarlar gələcək tətbiq testləridir; hazırda keçmiş test nəticəsi deyil.

## İcra ardıcıllığı

| Mərhələ | İşlək nəticə | Əsas yoxlama |
| --- | --- | --- |
| M1 — Təməl | Next.js, Supabase migrations, tenant/üzvlük/rol/departament, Auth/MFA, layout | İki tenant, pending/suspended, role spoofing, səlahiyyət ləğvi |
| M2 — Müştəri bazası | Admin Excel importu, Map/list/pin, müştəri/filial seçimi | 2 500 sətir, retry, malformed fayl, tenant və yazma hüququ |
| M3 — CRM və To Do | İki qıf modeli, sales Kanban/list, qutu/iş/task, audit/rəy/bildiriş, şəxsi/ortaq təqvim | Status/qiymət/deadline/assignee, concurrency, Realtime; pilot hazır ola bilər |
| M4 — Əməliyyat | Tools, Meetlər, Users, sales Portfel, Drive linkləri, Gmail keçidi | Tutum, material/profile privacy, mobile əsas axın |
| M5 — Maliyyə və abonent | Balans, payment/allocation/adjustment, müqavilə və aylıq generation, dövri payment display, monthly Portfel, Overview | Retry/double charge, 50%, stop/resume, short month, financial isolation |
| M6 — Tam v1 | Ümumi webhook, Inbox chat, bütün modulların son axını, export, deployment/runbook/backup | End-to-end, auth email, load/mobile, real resource config, restore |
| M7 — Sonrakı məhsul | Müştəri kabineti, tam Google, SaaS paketləri və digər adapterlər | Ayrı gələcək tapşırıq; v1-i bloklamır |

M1-dən tenant izolyasiyası qurulur. M3 satış hadisələrinin kontraktını yaradır; M4 Portfel onları istifadə edir, M5 maliyyə event-lərini aktivləşdirəndə əvvəlki uyğun mənbələri idempotent backfill edir. Maliyyə modulu hazır olmayanda saxta sıfır Balans göstərilmir.

Qurulma əmri bütün v1 üçündürsə mərhələləri kiçik işlək axınlarla M6-ya qədər davam etdir; ayrıca hər mərhələ üçün yeni icazə istəmə. Yerli build/test və əlçatan konfiqurasiya işlərini tamamla. Həqiqətən çatışmayan hesab/fayl məlumatını [qurulma təhvil sənədinə](08-qurulma-tehvil.md) yaz; müstəqil modulları saxlamır. Production/DNS/xərc əməliyyatları verilmiş konkret qurulma səlahiyyətinə uyğun aparılır.

## Qəbul meyarları

Əvvəlki AC-01–64 identifikatorları saxlanılıb, yekun seçimlərə uyğunlaşdırılıb; AC-65–76 yeni seçimlərin nəticələridir. Testləri modula uyğun seç. Sırf reversiv mətn/UI dəyişikliyi üçün implementation-u təkrarlayan test yazma. Schema/RLS, pul, vaxt, icazə və paralel əməliyyat testləri məcburidir.

- **AC-01:** A və B agentlikləri, iki departament və müxtəlif rollarla test məlumatı qurulur. A admini B-nin qutusunu API, UI, ixrac, URL və Realtime vasitəsilə oxuya/yaza bilmir.
- **AC-02:** Qeydiyyatdan keçən pending istifadəçi agentlik məlumatı görmür. Dəvət yalnız uyğun hesab, vaxt və agentlik üçün işləyir; qəbul təkrarı əlavə üzvlük yaratmır.
- **AC-03:** Giriş, çıxış, e-poçt təsdiqi və Reset Password real test SMTP-si ilə işləyir; redirect yalnız icazəli origin-ə gedir.
- **AC-04:** Adi üzv rolunu və departamentini öz istəyi ilə dəyişə bilmir. Üzvlük dayandırıldıqda yeni əməliyyatlar rədd edilir, açıq sessiya və kanalların davranışı yoxlanır.
- **AC-05:** Balans icazəsiz əməkdaş üçün ilkin olaraq bağlıdır. Rol/fərdi icazə veriləndə əməkdaş bütün agentliyin maliyyəsini, o cümlədən digər departamentlərin maliyyə qeydlərini görür; başqa agentliyi görə bilmir. İcazə bağlananda agentlik üzrə Balans məlumatı UI, API, maliyyə audit payload-u, export, Overview və Realtime-da görünmür; ümumi keş və abunələr təmizlənir. Qutunu yaradanın öz qutusunda D39 üzrə dar ödəniş hüququ AC-44 ilə ayrıca yoxlanır. Qutu qiymətinin `commercials.read` hüququ müstəqil açılıb-bağlanır; Balansın açılması tam CRM qutusu və tapşırıq hüquqlarını genişləndirmir. Oxuma yazma/ixrac hüququ vermir.
- **AC-06:** Kanban və siyahı eyni filtr altında eyni icazəli qeydləri göstərir. Hər sütun daxili scroll edir, minlərlə kart səhifəni sonsuz uzatmır.
- **AC-07:** Başlıq boş olanda server unikal seriya verir. Əl ilə yaradılan qutuda server sessiyasındakı üzv həm yaradan, həm ilkin cavabdeh olur; saxta creator payload-u qəbul edilmir. Paralel iki yaradılma eyni nömrə almır; eyni request-in təkrarı iki qutu yaratmır. Sonrakı səlahiyyətli təyinat yaradan sahəsini dəyişmir.
- **AC-08:** Deadline və qiyməti boş olan lead yaranır. Təsdiq və birbaşa icra/təhvil keçidi deadline və ya aktiv işlərin məlum qiymət cəmi olmadan UI və alternativ API-dən rədd olunur. Heç bir işi olmayan və ya bir iş qiyməti NULL olan qutuya manual total yazaraq keçid mümkün deyil. Şərtlər tamamlananda keçid, tarixçə və bildiriş yaranır; təsdiqlənmiş sifarişin qiyməti sonradan NULL edilə bilmir.
- **AC-09:** Qutu yaradılan/iştirakçı əlavə edilən zaman aidiyyəti istifadəçi bir bildiriş alır. Şərhdə mention qutu hüququndan kənar məlumat açmır.
- **AC-10:** Eyni `version` ilə iki paralel status dəyişikliyindən biri uğurla yazılır; digəri konflikt göstərir. Heç bir dəyişiklik izsiz itmir.
- **AC-11:** CRM-də əməkdaşın üzv olduğu departamentlərin bütün qutuları və ayrıca təyin edildiyi digər departament qutusu görünür. To Do-nun ilkin siyahısı və təqvimi özünə təyin olunan CRM işləridir; ortaq sifariş baxışında iştirak etdiyi sifarişin işləri də görünə bilər, admin bütün işləri görür. Eyni məlumat hüquqları qutu popup-u, profil təqvimi və birbaşa API üçün də yoxlanır.
- **AC-12:** Tapşırıq statusu/deadline dəyişəndə siyahı və təqvim uyğun yenilənir. Azərbaycan vaxtı ilə gün sərhədi düzgün göstərilir.
- **AC-13:** Realtime hadisəsi iki açıq icazəli brauzerdə ölçülür. Dublikat/köhnə hadisə tətbiq edilmir. Bağlantı kəsilib bərpa ediləndə məlumat bazadan yenilənir.
- **AC-14:** Təxminən 2 500 müəssisəli XLSX/CSV importu preview/mapping/konflikt/xətaları göstərir, progress və nəticə hesabatı verir. Yeni müəssisə importdan yaranır, Map/CRM-də ayrıca create form yoxdur. Yalnız admin import/düzəliş edir; read-only əməkdaşın direct API cəhdi rədd olunur. Fayl/expanded-size/sətir limitləri yoxlanır.
- **AC-15:** Telefonun `+` və başlanğıc sıfırları, Azərbaycan hərfləri, decimal separator və boş xanalar düzgün işlənir. Eyni fayl təkrarı uyğunlaşdırma siyasətinə əsasən dublikat yaratmır.
- **AC-16:** Koordinatlı qeyd düzgün marker olur; yalnız ünvanlı qeyd siyahıda və tamamlanma filtrində qalır. Lat/lng qarışması və yanlış interval aşkarlanır. Əl ilə düzəldilən pin təkrar importda itmir.
- **AC-17:** Eyni müştərinin iki filialı ayrıca qalır. İki fərqli agentliyin eyni adlı müştərisi avtomatik birləşdirilmir.
- **AC-18:** İxrac filtr və icazələrə uyğundur; mətn hüceyrələrində formula injection yoxlanır. Endirmə linki başqa agentlikdən işləmir.
- **AC-19:** Yanlış imzalı webhook rədd edilir. Doğru webhook ilkin cavabdehi həmin agentliyin konfiqurasiya edilmiş admini olan bir lead yaradır; mənbə webhook-dur, insan yaradıcısı saxtalaşdırılmır. Retry dublikat qutu/bildiriş yaratmır və sonradan dəyişdirilmiş cavabdehi adminə qaytarmır. Uyğun admin tapılmaması görünən təyinat xətası yaradır, qəbul edilmiş lead itmir. Natamam məlumat görünür; worker dayanandan sonra iş davam edir.
- **AC-20:** Qutuya əlavə edilən link Drive bölməsində eyni qeyd kimi görünür. Google-da giriş olmayan fayl CRM tərəfindən ictimailəşdirilmir. Gmail keçidi düzgün açılır və API inteqrasiyası kimi təqdim olunmur.
- **AC-21:** Satış qıfında təsdiq Portfeldə bir qaralama yaradır, təhvil həmin qeydi tamamlanmış edir; bu, qutuda açıq iş olsa da keçərlidir. İş statusları ayrıca qalır. Hadisənin təkrarı dublikat yaratmır; M4-dən əvvəl təsdiqlənmiş qeydlər idempotent uyğunlaşdırılır. Dövri aylıq qutu ayrıca yeni layihə kartı yaratmır; AC-58-dəki şirkət xülasəsinə bağlanır.
- **AC-22:** Eyni kameranı eyni vaxta iki nəfər rezervasiya etməyə çalışanda biri rədd edilir. Tutumu birdən çox alətlər razılaşdırılmış capacity qaydasını qoruyur.
- **AC-23:** Əyani/online görüşün iştirakçıları, müddəti və məkan/linki düzgün saxlanır. Tarix, siyahı və təqvim eynidir.
- **AC-24:** 1 000 AZN alacaq və 300 AZN ödəniş 700 AZN qalıq verir; 200 AZN öhdəlik və 50 AZN çıxış 150 AZN borc verir. Avans, reversal, qiymət dəyişikliyi və artıq allocation ayrıca sınaqdan keçir.
- **AC-25:** Eyni ödəniş retry ilə iki dəfə yazılmır; iki paralel allocation ümumi məbləği aşa bilmir. Lost statusu pul tarixçəsini silmir.
- **AC-26:** Hər aktiv aylıq dövr üçün bir qutu, iş dəsti və əsas alacaq yaranır; gecikən ödəniş generation-u saxlamır. Satış/müqavilə/dövri mənbə eyni xidməti iki dəfə borclandırmır. Retry/paralel worker/yarımçıq icra bərpası dublikat yaratmır. Qısa ay AC-64, pause/stop və cari haqq S01/S22, snapshot AC-63 üzrə yoxlanır.
- **AC-27:** Overview göstəriciləri eyni dövrün baza sorğuları ilə tutuşdurulur. Razılaşdırılmış satış məbləği daxil olmuş pul kimi göstərilmir; eyni sifariş iki dəfə sayılmır.
- **AC-28:** 360 px, planşet və desktop ölçülərində əsas axınlar işləyir: login → müştəri seçimi → qutu yaratmaq → status dəyişmək → tapşırıq → şərh. Menyuda bütün 12 bölməyə çıxış var.
- **AC-29:** Sürükləməyə alternativ status əmri, klaviatura fokusu, modal bağlanması və səhv formanın aydın mesajı işləyir.
- **AC-30:** 15 paralel istifadəçi, 2 500 müəssisə, 10 000 qutu və 40 000 işdən ibarət sintetik dataset ilə ölçmə aparılır; qutu/iş həcmləri istifadəçinin real rəqəmləri kimi təqdim edilmir. Cihaz/şəbəkə/p95/soyuq-isti start ayrıdır; docs/02 hədəfləri ilə müqayisə verilir.
- **AC-31:** Arxitektura sənədindəki P95 hədəfləri test şəraiti və faktiki nəticələrlə ölçülür. Hədəfə çatmayan hissə üçün səbəb və düzəliş təqdim olunur; “sürətlidir” demək kifayət etmir.
- **AC-32:** Backup-dan ayrılmış mühitə bərpa məşqi, fon işi bərpası, migration uyğunluğu, loglarda məxfi məlumat və aylıq xərc yoxlanır.
- **AC-33:** Admin paneldən yeni rol yaradır, adını/icazələrini dəyişir və üzvə təyin edir; kod dəyişikliyi tələb olunmur. Adi əməkdaş rol yarada, özünü admin edə və fərdi grant saxtalaşdıra bilmir. Rol/fərdi icazə üzrə inherit/allow/deny nəticəsi razılaşdırılmış qayda ilə yoxlanır; rol adını “Admin” etmək hüquq qazandırmır. Son aktiv admin və istifadəçili rolun silinmə qaydası yoxlanır.
- **AC-34:** Yaradan və cavabdeh ayrı üzvlər olanda hər ikisi qutunu redaktə edir; yalnız iştirakçı və ya departament üzvü olan şəxs eyni qutunu dəyişə bilmir. Admin yaratmadığı/cavabdehi olmadığı qutunu da dəyişir. Departament oxuma icazəsi redaktə icazəsi kimi istifadə edilmir; yoxlama UI, sürükləmə və birbaşa API-də işləyir.
- **AC-35:** Admin, yaradan və hazırkı cavabdeh aktiv agentlik üzvünü yeni cavabdeh təyin edə bilir. Yaradan sahəsi dəyişmir, yeni cavabdehə bildiriş və audit yaranır. Köhnə cavabdeh yaradan/admin deyilsə bu təyinatdan gələn redaktə hüququnu itirir. İcazəsiz özünütəyin, başqa agentlik/deaktiv üzv təyinatı və paralel köhnə versiyalı dəyişiklik rədd edilir.
- **AC-36:** Admin xidməti kataloqa əlavə edir, dəyişir və arxivləşdirir. Qutuya xidmət əlavə ediləndə departament, qiymət və iş cavabdehi ayrıca saxlanır. Kataloq/standart qiymət dəyişməsi mövcud sifarişin qiymət və ad/təsvir snapshot-unu dəyişmir. Başqa agentliyin kataloqu, departamenti və üzvü sətrə bağlana bilmir.
- **AC-37:** Bir qutuda Development və Marketing işi yaradılır: qutu hər iki departament filtrində görünür, ümumi siyahı/ixrac/saylarda bir dəfədir. Son departament işi arxivləşəndə görünüş və canlı abunələr cari hüquqlara uyğunlaşır; digər əsasla giriş hüququ olanlar saxlanır. Departament üzrə satış məbləği öz iş qiymətlərindən hesablanır; ümumi satış iki dəfə sayılmır.
- **AC-38:** 1 000 və 300 AZN iş qiymətləri 1 300 AZN qutu yekunu verir. İşin qiymətini 350 AZN etmək yekunu 1 350 AZN edir; ayrıca endirim/manual total mümkün deyil. NULL iş qiyməti yekunu “tamamlanmayıb” edir. Paralel iki qiymət yazması və təsdiq əməliyyatı köhnə cəmi saxlamır. İş qiymətləri kommersiya icazəsi bağlı olduqda API/ixrac/audit/Realtime-dan sızmır; ödəniş məbləği iş qiyməti dəyişəndə yenidən yazılmır.
- **AC-39:** İş cavabdehi öz iş statusunu dəyişir; yalnız iş cavabdehi olan şəxs ümumi qutunu, başqa işin statusunu və işin qiymət/departament/cavabdeh/deadline sahələrini bu endpoint-lə dəyişə bilmir. Əlavə ümumi redaktə hüququ varsa ayrıca yoxlanır. İşin öz deadline-ı, qutu deadline-ı və To Do/təqvim görünüşü uyğun saxlanır; iş statusu iki fərqli kopyada ayrılmır.
- **AC-40:** Təsdiqi, qiyməti və ümumi deadline-ı tam olan qutuda açıq iş/tapşırıq qalarkən səlahiyyətli şəxs təhvil keçidini edə bilir. Qutu və Portfel uyğun yenilənir, açıq işlər tamamlanmış sayılmır, silinmir və To Do/təqvim/gecikmə statistikasından çıxmır. İş cavabdehi sonradan öz iş statusunu yeniləyə bilir; bu, qutunu avtomatik geri açmır. İcazəsiz istifadəçi açıq iş istisnası ilə təhvil hüququ əldə etmir.
- **AC-41:** Qutu və işdə tarix+saat seçilir. İş deadline-ı ümumi qutu deadline-ına bərabər və ya daha erkəndirsə qəbul edilir, gecdirsə rədd olunur; eyni gündə 18:00 parent üçün 19:00 iş də rədd edilir. İş vaxtının sərhəd daxilində uzadılması işləyir; daha gec vaxt üçün əvvəlcə ümumi deadline uyğun uzadılır. Parent vaxtını mövcud iş vaxtlarından əvvələ çəkmək, o cümlədən paralel iş uzatması zamanı invariantı pozmaq mümkün deyil. Tarixlər səssiz dəyişmir, UTC/agentlik timezone göstərimi, audit/bildiriş və UI/API yoxlamaları uyğundur. Lead-də parent tarix hələ boşdursa ilkin iş vaxtları parent təyin ediləndə və təsdiqdə yoxlanır.
- **AC-42:** Admin iş qiymətini dəyişir. Qutunun yaradanı və hazırkı cavabdehi yalnız ayrıca commercials.write aktiv olduqda qiymət yaza bilir. Qutu redaktorunun bu icazəsiz, başqa üzvün yalnız bu icazə ilə və ya iş cavabdehinin yalnız öz iş statusu hüququ ilə qiymət dəyişməsi rədd edilir. İcazə rol/fərdi səviyyədə ləğv ediləndə açıq sessiyada növbəti yazma da rədd edilir; mövcud qiymət cəmi və audit pozulmur.
- **AC-43:** Səlahiyyətli istifadəçi Lost-a səbəb seçmədən keçə bilmir. Səbəb seçilib mətn qeydi boş qaldıqda keçid işləyir; istəyə bağlı qeyd veriləndə saxlanır. Yanlış/başqa agentlik səbəbi, alternativ API ilə səbəbsiz keçid və icazəsiz actor rədd olunur. Qeyd ləğv ediləndə sürüklənmiş kart canonical mərhələsinə qaytarılır; uğurlu keçiddə mərhələ, səbəb, vaxt və audit uyğun yazılır.
- **AC-44:** Admin agentlik daxilində sifariş ödənişi daxil edib düzəldir. Qutu yaradanı `finance.read` bağlı olsa da öz qutusunda ödənişi daxil/düzəliş edə və həmin əməliyyat üçün dar ödəniş qeydlərini görə bilir; ümumi Balans, digər qutular, maliyyə ixracı və agentlik cəmləri açılmır. Təkcə hazırkı cavabdeh, iş cavabdehi, commercials.write və ya finance.read olan başqa üzv ödəniş yaza bilmir. Cavabdehin dəyişməsi yaradanın hüququnu daşımır; webhook qutusunda insan yaradan yoxdursa adi cavabdeh yaradan kimi hüquq almır. Tenant/üzvlük, əvvəlki/yeni qutu əlaqəsi, audit və paralel düzəliş yoxlanır. Üzvlük dayandırılanda dar giriş də bağlanır.
- **AC-45:** Qiyməti məlum 1 000 AZN birdəfəlik sifariş təsdiqdə bir ilkin alacaq yaradır. 300 AZN ödənişdən sonra təhvildə qalıq 700 AZN qalır; alacaq 2 000 AZN olmur, avtomatik pul daxilolması yazılmır. Ödənişsiz təhvildə qalıq 1 000 AZN-dir. Təsdiq/təhvil retry-si, təkrar təsdiq və paralel hadisələr bir ilkin mənbə üzrə dublikat yaratmır. Təsdiq hüquqlu hazırkı cavabdeh yaradan olmasa da normal təsdiq keçidini edə bilir; bu, ona əl ilə ödəniş yazmaq hüququ vermir. Sonrakı qiymət dəyişməsi mövcud ödənişi və ilkin alacağı izsiz yeniləmir.
- **AC-46:** Frilanser, təchizatçı, əməkdaş haqqı və ofis xərcləri üzrə öhdəliklər ayrı kateqoriyalarla saxlanır və cəmlənir. 200 AZN öhdəlikdən 50 AZN ödəniş sonra 150 AZN borc qalır; kateqoriya filtrindəki məbləğ ümumi nəticəyə ikinci dəfə əlavə edilmir. Bu qeydlərdən avtomatik əməkhaqqı/vergi hesablanması və ya CRM xidmət qiymətinə bərabər xərc yaradılmır.
- **AC-47:** CRM-də Yeni müştəri qıfının səkkiz mərhələsi, Dövri qıfında isə Ödəniş olunmayıb / İcra olunacaq / İcrada / Bitdi sütunları görünür. Aylıq qutu yalnız Dövridədir; gecikmiş ödənişdə 50% tamamlanmayıbsa Ödəniş olunmayıb sütununda, xəbərdarlıq yoxdursa saxlanmış cari icra sütununda görünür. İlk satış qeydi yerində qalır. Kanban/siyahı, daxili scroll, mobil idarə və Realtime uyğun işləyir. Başqa qıf mərhələsi, satış qıfına adi daşınma və maliyyə əsası olmadan ödəniş xəbərdarlığını söndürən API rədd edilir; qıf/tenant/obyekt filtrləri keş və saylarda da qorunur.
- **AC-48:** İki ardıcıl ay üçün fərqli dövri qutu və iş ID-ləri yaranır; əvvəlki ayın işləri, rəyləri, ödənişləri və tarixçəsi saxlanır. To Do/təqvim həmin iş ID-lərini göstərir, statusun ayrıca zidd kopyası yoxdur. Təyinat və departament hüquqları tətbiq edilir. Yeni aylıq qutu yeni lead və ya yeni qazanılmış satış sayılmır; iş yükü hər iki qıfdan düzgün toplanır.
- **AC-49:** Müqavilələrin ödəniş günləri ayrı saxlanır və birinin dəyişməsi digərinə təsir etmir. Planlaşdırılmış tarix faktiki pul daxilolması kimi yazılmır, iş deadline-ı ilə qarışdırılmır. Dövri Bitdi/Portfel və ilkin deadline qaydaları AC-57–59-da ayrıca yoxlanır.
- **AC-50:** Təsdiq 5-i, ilk planlaşdırılmış ödəniş 12-si, faktiki pulun gəlməsi 15-i nümunəsində dövr 12-dən başlayır. 15-də ödəniş daxil edilməsi əvvəl yaranmış dövrü başqa tarixlə təkrar yaratmır, qutu/iş deadline-larını və növbəti ayların planını sürüşdürmür. Dövr yaranması zamanı faktiki pul yazılmır.
- **AC-51:** Ödəniş geciksə həmin dövrün qutusu, işləri və alacağı yenə bir dəfə yaranır; 50% həddi tamamlanmayıbsa qutu Ödəniş olunmayıb sütununda, işlər To Do/təqvimdə görünür. Qutuya girişli, maliyyə icazəsiz əməkdaş etiketi görür, lakin həmin etiket vasitəsilə borc məbləği/ödəniş tarixçəsi/ixrac hüququ almır. Başqa agentliyin qutusu və etiketi də bağlıdır; gizli məbləğ audit və Realtime-da sızmır.
- **AC-52:** Avtomatik qutu sistem mənbəyi ilə yaranır və ilkin insan yaradan hüquqları admində qalır. İlkin satış/müqavilə yaradanı yalnız mənbə əlaqəsinə görə ödəniş və yaradana aid redaktə hüququ almır. Ayrıca təyin olunmuş qutu cavabdehi ümumi qutunu redaktə edə bilər, lakin bu əsasla ödəniş yaza bilməz. Adminin hüquqları cari tenant/üzvlükdən yoxlanır; səlahiyyət itkisindən sonra tarixi ad əsasında giriş qalmır.
- **AC-53:** Ödəniş xəbərdarlığı göstəriləndə saxlanmış icra vəziyyəti və iş statusları itmir. Paralel icra dəyişikliyi, ödəniş düzəlişi və hadisə retry-si köhnə icra vəziyyətini geri yazmır və maliyyə qeydlərini təkrarlamır. 50% həddinə çatanda cari icra sütunu görünür; texniki yenidən hesablama üzrə etibarlı reversal həddi aşağı salarsa vaxtı keçmiş öhdəlikdə ödəniş xəbərdarlığı yenidən görünür, icra tarixçəsi dəyişmir. Sütun əmri pul saxtalaşdıra bilmir.
- **AC-54:** Ödəniş olunmayıb sütunundakı qutunun iş cavabdehi öz işini başladıb statusunu yeniləyir; To Do/təqvim eyni vəziyyəti göstərir. Bu hüquqla başqa işi, qutunun mərhələsini və qiymətini dəyişə bilmir. Qutu redaktoru kartın saxlanmış icra mərhələsini İcrada edir; 50% hələ ödənmədiyi üçün kart ödəniş sütununda qalır, hədd tamamlananda isə İcrada görünür. Yeni qutu İcra olunacaq, artıq Bitdi kimi saxlanmış qutu Bitdi sütununa qayıdır. Açıq işlərlə həqiqi Bitdi keçidi AC-57 üzrə səbəb tələb edir; ödənişdən sonra əvvəlki Bitdi görünüşünə dönüş təkrar tamamlama deyil.
- **AC-55:** 1 000 AZN dövr üzrə 499,99 AZN kifayət etmir, 500 AZN dəqiq həddə çatır; qalıq 500 AZN qalır və tam ödənilmiş statusu yaranmır. 200+300 AZN etibarlı ödəniş cəmi də eyni nəticə verir. Başqa ay/müştəri pulu, bölüşdürülməmiş avans və planlaşdırılmış ödəniş həddi tamamlamır. 1 000,01 AZN dövr üçün 500,00 AZN yetmir, 500,01 AZN yetir; yuvarlaq ekran faizi qərar mənbəyi deyil.
- **AC-56:** 50% həddi ilə sütun dəyişəndə real pul, qalıq borc, iş deadline-ları, dövr tarixləri və satış statistikası dəyişdirilmir. İcazəli iki açıq sessiya cari icra sütununu uyğun görür; maliyyə icazəsi olmayan sessiya hadisədə məbləğ almır. Həddə çatdıran paralel hissəli ödənişlər/iş statusu və təkrar hadisələr əvvəlki sütuna səhv reset, ikinci alacaq və ya təkrar ödəniş yaratmır.
- **AC-57:** Dövri qutuda açıq iş/alt tapşırıq olduqda Bitdi əmri boş və yalnız boşluqdan ibarət səbəblə UI/API-də rədd edilir. Səlahiyyətli qutu redaktoru səbəb yazanda keçid baş verir; səbəb, açıq işlər, müəllif və vaxt auditdə saxlanır. İşlər tamamlanmır, To Do/təqvimdən çıxmır və öz cavabdehləri statusu yeniləyə bilir. Bütün işlər tamamdırsa səbəb məcburi deyil. Səbəb dialoqunu ləğv etmək, paralel iş yaratmaq və icazəsiz keçid qaydanı aşmır. Ödəniş həddinə görə Bitdi görünüşünə dönüş təkrar səbəb istəmir.
- **AC-58:** Eyni şirkətin aylıq dövrləri yeni Portfel layihə kartı yaratmır, icazəli Bitdi dövrlərinin xidmət intervalları bir xülasədə birləşir. Üst-üstə düşən günlər bir dəfə, fasilə/future günlər sıfır sayılır. Reopen dövr töhfəsini müvəqqəti çıxarır, re-done eyni mənbəni bərpa edir. Retry və payment-display dönüşü müddəti artırmır. Açıq iş səbəbi və tenant/source hüquqları qorunur, satış AC-21 davranışı qalır.
- **AC-59:** Sərhədləri 12 sentyabr və 12 oktyabr olan aylıq qutunun ilkin ümumi deadline tarixi 11 oktyabrdır. Seçilmiş T13 qaydasında saat 23:59 Asia/Baku kimi daxil edilir və UTC-dən geri göstərim eyni yerli vaxtı verir. Gecikən ödəniş bu tarixi dəyişmir. Əl ilə uzatma iş deadline sərhədini qoruyur, xidmət/ödəniş dövrünü və Portfel müddətini dəyişmir; generation retry əl ilə redaktəni əvəz etmir. Ayrı işlərin daha gec deadline-ı rədd edilir; qısa ay nümunələri AC-64-dədir.
- **AC-60:** Marketing və Development üzvlüyü olan əməkdaş hər iki departamentin qutularını görür; eyni qutu siyahı/sayda təkrarlanmır. Yalnız Marketing üzvü başqa departamentin bir qutusundakı işə təyin ediləndə həmin qutunu görür, departamentin digər qutularını görmür və tək iş təyinatı ilə ümumi qutunu dəyişə bilmir. Son təyinat ləğv ediləndə başqa giriş əsası yoxdursa API/keş/Realtime girişi bağlanır; ayrıca departament üzvlüyü və ya digər qüvvədə olan əsas varsa uyğun baxış qalır. Özünü icazəsiz təyin etmə və başqa tenant üzvünə təyinat rədd olunur.
- **AC-61:** Eyni agentliyin bütün active üzvləri müəssisə/filial bazasını görə bilir; koordinatsız qeyd siyahıda qalır. Başqa tenant/suspended üzv məlumatı oxuya bilmir. Map read qutu/maliyyə/import faylı/export hüququ vermir. Admin import/düzəliş edir; naməlum webhook müəssisəsi intake-də qalır, sonrakı importdan sonra eyni lead-ə bağlanır.
- **AC-62:** CRM qutusunda iş əməkdaşa təyin ediləndə eyni mənbə ID-si onun To Do siyahısı və təqvimində görünür; ayrıca To Do yaratma əməliyyatı lazım deyil. Təyinat dəyişəndə köhnə/yeni cavabdehin “Mənim işlərim” görünüşü uyğun yenilənir; əvvəlki əməkdaşın ortaq sifarişə ayrıca baxışı qala bilər. Yeni müştəri və Dövri qutuları eyni qaydanı qoruyur; ümumi qutu cavabdehinə bütün alt işlər özünə təyin olunmuş sayılmır. Sifarişsiz tapşırıq və hüquqsuz təyinat UI/API-də qəbul edilmir. Açıq işlər təhvil/Bitdi səbəbindən gizlənmir.
- **AC-63:** Müqavilədə seçilmiş işlər, cavabdehlər və tarix planı iki ardıcıl dövrə avtomatik tətbiq olunur; yeni ayın iş ID-ləri ayrıdır, tarixlər yeni dövrə aiddir, əvvəlki ayın tamamlanmış statusları daşınmır. İşlər eyni ID-lərlə To Do-da görünür. Şablon dəyişəndə yaranmış ayın surəti qorunur, növbəti dövr yeni versiyanı alır; paralel generation/retry eyni dövrə qarışıq versiya və təkrar iş yazmır. Qutu sərhədini keçən tarix və passiv/başqa tenant cavabdehi ilə iş hazır kimi yaradılmır; görünən xəta və bərpa statusu saxlanır. Başqa agentliyin şablonunu oxuma/tətbiq etmə rədd edilir.
